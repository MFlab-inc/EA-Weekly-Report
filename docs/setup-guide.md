# セットアップ・並行運用開始 手順書（しょうさん向け）

対象: GitHub Web UIのみでの操作（コマンドライン不要。HANDOFF.md §運用方針どおり）。
所要時間の目安: 約15分。

前提: リポジトリ（MFlab-inc/EA-Weekly-Report）は作成済み・コードは全てpush済みです。残っているのは
「本番ワークフローを有効化する」「GitHub Pagesを有効化する」の2点と、その後の並行運用です。

---

## 手順1: 週次配信ワークフローを本番へ移設するPRをマージする

`weekly.yml`（毎週の自動生成本体）は、これまで本番の`.github/workflows/`ではなく
`workflows-draft/`に置いていました（誤って毎週動き出さないための安全策）。これを本番へ
移すPRを作成しますので、レビューしてマージしてください。

1. Claude（このセッション）に「weekly.ymlを本番へ移設するPRを作成してください」と伝えてください（このドキュメントの生成と同時にPRを作らなかったのは、勝手にPRを作らない方針のためです）
2. GitHubでリポジトリを開き、上部タブの **「Pull requests」** を開く
3. 該当PRを開き、変更内容（`.github/workflows/weekly.yml`が新設され、`workflows-draft/weekly.yml`が削除される差分）を確認
4. 問題なければ緑色の **「Merge pull request」** ボタン → **「Confirm merge」** を押す

このPRがマージされると、以下の3ジョブが有効になります（`workflows-draft/weekly.yml`のコメント参照）:

| ジョブ | 実行タイミング | 内容 |
|---|---|---|
| `build` | 毎週土曜 08:06 JST（保険で08:41にも再実行） | 収集→台帳生成→レンダリング→監査→`output/`へコミット |
| `deploy-pages` | `build`成功直後 | `output/`配下のレポートをGitHub Pagesへ公開 |
| `monday-ff-cross-check` | 毎週月曜 08:23 JST | Forex Factoryとの事後突合（相違があれば失敗して通知） |

手動でいつでも起動することもできます（手順4参照）。

---

## 手順2: GitHub Pagesを有効化する

1. リポジトリの **「Settings」**（歯車アイコン）タブを開く
2. 左メニューの **「Pages」** を開く
3. **「Build and deployment」** → **「Source」** のプルダウンで **「GitHub Actions」** を選択する（「Deploy from a branch」ではありません。これを間違えると`deploy-pages`ジョブが失敗します）
4. 保存は自動です（プルダウンを選ぶだけで反映されます）

---

## 手順3: Actions権限を確認する

1. 同じ **「Settings」** → 左メニュー **「Actions」** → **「General」** を開く
2. 下の方の **「Workflow permissions」** で **「Read and write permissions」** が選択されていることを確認する（`build`ジョブが`output/`・`data/`をリポジトリへコミットするために必要）
3. 選択されていなければ選んで **「Save」**

### FRED_API_KEYについて（確認のみでOK）

米国GDP等の一部データ取得元（FRED = セントルイス連銀の経済データAPI）用のAPIキーです。
**既にtask #41のライブ検証で実際に使われて動作確認済みのため、新規登録は不要**です。念のため
**「Settings」→「Secrets and variables」→「Actions」** を開き、`FRED_API_KEY`が一覧にあることだけ確認してください。無ければClaudeに再登録の要否を相談してください。

---

## 手順4: 手動で1回動かして動作確認する

1. リポジトリの **「Actions」** タブを開く
2. 左側のワークフロー一覧から **「weekly-report」** を選ぶ
3. 右側の **「Run workflow」** ボタン → ブランチは`main`のまま → 緑の **「Run workflow」** を押す
4. 数分待って、実行結果に緑のチェックマーク✅が付けば成功です（`build`→`deploy-pages`の順に走ります。`monday-ff-cross-check`は月曜のcronでのみ動くため、この手動実行では動きません）
5. 失敗（赤い✕）の場合は、該当runを開いてログを確認するか、Claudeへ「weekly-reportの手動実行が失敗した」と伝えてください

---

## 手順5: プレビューページを確認する

手順4の`deploy-pages`が成功すると、以下のURLでレポート一覧が見られるようになります（初回反映まで数分かかることがあります）:

**`https://mflab-inc.github.io/EA-Weekly-Report/`**

このページから各週のレポート（`ea-weekly-YYYYMMDD.html`）へ直接リンクしています。新しい週が
一番上（「最新」バッジ付き）に表示されます。このURLはブックマークしておくと便利です。

（`Settings → Pages` の画面上部にも同じURLが「Visit site」ボタン付きで表示されます）

## 手順6: 並行運用（1〜2週間の目安）

rebuild-plan_v0.3.mdの方針どおり、いきなり本パイプラインへ切り替えるのではなく、
**現行Manus配信と本パイプラインの出力を1〜2週間突き合わせて検収**してください。

- 毎週土曜、上記プレビューURLで新しいレポートを確認する
- 現行Manus配信の内容と見比べ、掲載イベント・時刻・停止スケジュールに差異が無いか確認する
- 差異があれば（既刊側の掲載漏れの可能性も含め）Claudeへ共有してください。`docs/validate-scripts-guide.md`の方針により、新パイプライン側にしか無いイベントは「回帰」ではなく「既刊側の漏れの可能性」として個別に判断します
- 検収が済んだ時点で、現行Manus環境の停止時期を決定します（rebuild-plan §10-7）

### 月曜のFF事後突合が失敗した場合の見方

月曜08:23 JSTの`monday-ff-cross-check`が赤い✕になっている場合、FFフィードとの間で
発表時刻の相違が見つかっています（掲載漏れではなく「時刻がズレている疑い」の検知）。

1. **「Actions」** タブ → 失敗した`weekly-report`のrun → `monday-ff-cross-check`ジョブを開く
2. ログに相違の一覧（イベント名・台帳側の時刻・FF側の時刻）が出力されています
3. 画面下部の **「Artifacts」** から `discrepancy-report` をダウンロードすると、同じ内容がJSON形式で入手できます
4. 相違が実際の誤りだと判断した場合は、既に配信済みの記事を手動で訂正してください（自動訂正はしない設計です。SPEC §3.3）。判断に迷う場合はClaudeへ相談してください
