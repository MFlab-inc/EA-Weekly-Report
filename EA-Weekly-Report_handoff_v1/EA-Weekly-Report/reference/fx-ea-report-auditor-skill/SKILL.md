# FX・EAレポート精度監査

## 目的

FX・EAユーザー向け配信物を、**根拠を追跡できる状態で作成・監査する**。推測による補完を禁止し、事実、予想、解釈、EA運用上の注意を分離する。公開前に、日付・曜日・JST・夏時間・数値定義・重複箇所・WordPress HTMLを検査し、未解消エラーが1件でもあれば**配信保留**とする。

## 適用範囲と優先順位

このスキルは、週次EAレポート、日次FXレポート、経済カレンダー更新、過去原稿の修正、WordPress用HTMLの納品に適用する。既存のレポート固有スキルがある場合は、**本スキルの品質ゲートを先に通してから**、その固有のテンプレート・デザイン・ビルド手順に従う。デザイン原本・ユーザー指定のEA停止基準・プロジェクト固有の納品形式は変更してはならない。

## 必ず守る処理順序

次の順序を入れ替えない。

1. 対象日、対象期間、表示基準時刻（原則JST）、調査開始時刻を確定する。日付・曜日はプログラムで再計算する。
2. 入力原稿、承認済みデザイン原本、ユーザー指定の重要度、EA停止基準を分離して読み取る。テンプレート内の数値を事実として再利用しない。
3. **本文を書く前に根拠台帳を作成する**。`references/verification-schema.md` と `references/source-policy.md` を必ず読む。
4. 発表主体の一次情報を優先して台帳を埋める。検索結果の要約だけを根拠にせず、必ず該当ページを開いて対象期間・日時・タイムゾーン・単位を確認する。
5. 台帳の静的検査を実行する。

   ```bash
   python3 /home/ubuntu/skills/fx-ea-report-auditor/scripts/validate_ledger.py \
     evidence_ledger.json --strict
   ```

6. 検査が合格してから、承認済みテンプレートに台帳の正規化済みデータだけを反映して本文・HTMLを生成する。
7. 事実監査、内部整合性監査、HTML監査を分けて実行する。WordPress用HTMLは次を実行する。

   ```bash
   python3 /home/ubuntu/skills/fx-ea-report-auditor/scripts/validate_report.py \
     wordpress_report.html --ledger evidence_ledger.json --year 2026 --require-sources --strict
   ```

8. `ERROR`が0件でなければ、成果物に**「判定：配信保留」**を付け、WordPress用の完成版として納品・投稿しない。`WARNING`は内容を確認し、解消不能なら理由を非公開の監査記録に残す。
9. 合格時だけ、完成HTML、`判定：配信可`、確定修正の要約、当日再確認が必要な項目、主要一次情報を納品する。詳細な監査ログは公開本文に入れない。

## 根拠台帳の作成

新規台帳は次で作成する。作成後に必ず実データ・確認時刻・一次情報URLを入力する。スクリプトが作る空欄は事実ではない。

```bash
python3 /home/ubuntu/skills/fx-ea-report-auditor/scripts/create_evidence_ledger.py \
  --target-start YYYY-MM-DD --target-end YYYY-MM-DD \
  --research-started-at 'YYYY-MM-DDTHH:MM:SS+09:00' \
  --output evidence_ledger.json
```

台帳は非公開の作業ファイルとする。本文には、台帳で検証済みの数値・日時・短い出典リンクだけを反映する。

### 値の扱い

| 区分 | 必須の分離・表記 |
|---|---|
| 経済指標 | 前回値、改定値、予想値、結果を別フィールドにする。前月比・前年比、総合・コア、季節調整の定義を付ける。 |
| 発表時刻 | 発表元の現地日時・タイムゾーン・UTCオフセット・JST変換値を別々に保存する。夏時間を日付ごとに再計算する。 |
| 市況値 | 銘柄、値、時点、タイムゾーン、`NY終値`・`終盤値`・`参考値`・`遅延価格`などの定義、遅延有無を保存する。 |
| 休日・市場休場 | 祝日、現物市場、先物・デリバティブ、決済・短縮取引を別項目として確認する。 |
| 未取得値 | `未掲載`、`未公表`、`該当なし`のいずれかを明示し、常識・前週値・古い記事で補完しない。 |

## 一次情報と競合の処理

発表日時、結果、政策判断、統計値、国債入札、公式休場は発表主体の一次情報を最優先する。市場予想・重要度は経済カレンダーまたは調査会社の値として扱い、中央銀行・統計当局の公式見解と混同しない。市況の背景説明や終盤値は信頼できる通信社を利用できるが、一次情報の数値を上書きしてはならない。詳細な優先順位は `references/source-policy.md` を読む。

2つの値が異なる場合は、誤りと即断せず、終値と終盤値、現物と先物、速報と改定などの定義差を確認する。解消できない重要な競合がある場合は、本文で断定せず配信保留とする。公式ページに時刻がない場合は、慣例から推定せず`当日確認`と記録する。

## EAユーザー向けの注意表現

重要度の星だけで全EAの停止を義務化してはならない。ユーザー指定のEA停止基準がある場合のみ、その基準に従って停止候補時間を計算する。基準がない場合は`稼働設定の確認推奨`とし、停止時間を勝手に決めない。政策声明、記者会見、要人発言、突発ニュースは終了時刻を断定しない。利益保証・投資助言と受け取られる表現を避ける。

## WordPress HTMLの必須条件

承認済みのテンプレートがある場合は、配色、余白、カード構造、レスポンシブ設計を維持する。WordPress貼り付け用HTMLはHTML断片として生成し、`html`、`head`、`body`、`script`、`style`、`form`、追跡タグ、外部JavaScriptを含めない。画像を追加する場合は実際に公開環境から参照できるURLだけを使う。

イベントを複数セクションに掲載する場合は、台帳の同一イベントIDから描画する。イベント要素には次の属性を付与する。これにより日時・数値・件数の自動照合を可能にする。

```html
<div data-ea-event-id="us-cpi-2026-07-15"
     data-ea-event-date="2026-07-15"
     data-ea-event-time-jst="21:30"
     data-ea-event-country="US"
     data-ea-event-importance="3">
```

`data-ea-event-id`を各重複掲載箇所で統一し、表示する前回・改定・予想・結果には、`data-ea-field="previous"`、`revised`、`forecast`、`result`を付ける。台帳の `report_event_ids` と、ヒーロー・詳細表・優先イベント一覧の件数を一致させる。

## 配信可否の判定

| 判定 | 条件 |
|---|---|
| **配信可** | 重大な未検証項目が0件、曜日・JST換算エラーが0件、台帳・HTML監査エラーが0件、重要イベント件数の不一致が0件。 |
| **配信保留** | 上記のいずれかが1件以上、または一次情報が未取得・競合未解消・テンプレート原本不在・自動検査不能の場合。 |

## 禁止事項

空欄を常識・前週値・古い別サイトの数値で補完してはならない。公式に時刻がないイベントへ慣例時刻を付けてはならない。終値と終盤値、現物と先物、速報と確報を混同してはならない。重要度や市場予想を公式機関の発表として書いてはならない。出典URL、引用、確認済みという表現を捏造してはならない。監査前の原稿を最終版と呼んではならない。
