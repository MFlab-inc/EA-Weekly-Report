# EA週次レポート：表示仕様・経済指標名称統合ポリシー v1.0

**確定日：2026年8月2日（日本時間）**  
**改訂日：2026年8月9日（日本時間）**  
**適用開始：対象週の開始日が2026年8月3日以降のEA週次レポート**  
**適用範囲：共有カレンダー、根拠台帳、生成HTML、WordPress用HTML、スマホ監査、公開可否ゲート**

> この文書は、EA週次レポートにおける読者向けイベント表示の唯一の基準です。旧来の `SECTION 04`・`SECTION04`・`JST` 見出し表記、英語の経済指標名、横並び時刻列、左寄りの見出し帯に関する規定と競合する場合は、**本ポリシーを最優先**します。

## 1. 適用範囲と他レポートとの境界

EA週次レポートの読者向け構成は、以下の**3中核見出しと1つの独立補助セクション**です。

| 表示順 | 読者向けの固定見出し | 目的 |
|---:|---|---|
| 1 | **EA運用タイムテーブル** | 重要イベント前後のEA停止・再開の判断材料を示す。 |
| 2 | **対象週の注目イベント(日本時間)** | 対象週の確認済み重要イベントを、日本時間の日付別に示す。 |
| 3 | **EAリスク管理ポイント** | スプレッド、流動性、約定、時刻未公表等の実務上の留意点を示す。 |
| 4（独立補助） | **土日のBTC/USD EA運用に関する重要ガイド** | BTC/USDを週末に運用する利用者向けに、停止・Lot抑制・再開判断を示す。EAリスク管理ポイントの後、フッターの直前に置く。 |

EA週次レポートには、`SECTION 01`〜`SECTION 05`、`SEC 01`〜`SEC 05`、`SECTION 04`、`SECTION04` を読者向け見出し・説明文・カードラベルとして表示してはなりません。

Pattern A、Pattern B、Pattern CのSECTION番号、個別のイベント構成、各パターン専用のスマホ仕様は、当該パターンのスキル・仕様書に従います。本ポリシーの3中核見出し、独立BTC週末EAガイド、EA専用イベントカードを、EA週次以外へ誤適用してはなりません。

## 2. 経済指標名の読者向け日本語表記

### 2.1 基本原則

読者向けHTML、WordPress用HTML、共有カレンダーの「イベント」欄には、**日本人向けの日本語名称のみ**を掲載します。英語の公式名称・英語の統計名称は、出典URL、内部根拠台帳、検証ログに保持できますが、読者向けイベント名として表示してはなりません。

| 順位 | 名称の参照先 | 使用方法 |
|---:|---|---|
| 1 | [fxshihyo.com](https://fxshihyo.com/) | 同サイトの日別カレンダーにある日本語表記を、読者向け表示名の第一基準とする。 |
| 2 | [みんかぶFX 経済指標](https://fx.minkabu.jp/indicators) | fxshihyo.comに該当イベントの日本語表記がない場合だけ、補完参照として使用する。 |
| 3 | 発表主体の公式サイト | 日時、対象期間、実績、発表形式、発言者、一次情報URLの確認に使用する。公式の英語名称をそのまま読者向け名称に流用しない。 |

### 2.2 根拠台帳の必須フィールド

対象週開始日が2026年8月3日以降のEA週次台帳では、各掲載イベントに以下を必須とします。

| フィールド | 用途 | 読者向けHTMLへの出力 |
|---|---|---|
| `event_name` | 英語の公式名又は内部識別用名称 | 出力禁止 |
| `event_display_name_ja` | 読者向けの確定日本語名称 | 必ず出力 |
| `event_display_name_source` | `fxshihyo.com` 又は `みんかぶFX` | HTML属性・台帳で保持し、必要に応じて監査 |
| `event_display_name_source_url` | 日本語名称を確認したURL | 台帳に必須。出典欄へ載せる場合は補助カレンダーであることを明示 |
| `event_display_name_checked_at_jst` | 名称を確認した日本時間のISO日時 | 台帳に必須 |

`event_display_name_ja` は、空欄、英字のみ、英語名称の直訳未確認、又は内部名と同一の英語表記のままでは不合格です。名称に英字の略称（ADP、ISM、JOLTS、Ivey、PMI等）が含まれること自体は、fxshihyo.com又はみんかぶFXに同じ表記がある場合に限り許可します。

### 2.3 読者向け表記の例

| 指標の分類 | 読者向けの表示名 |
|---|---|
| 中国の製造業PMI | **RatingDog(旧財新)製造業PMI** |
| カナダの商品貿易 | **カナダ・国際商品貿易** |
| 米国の貿易統計 | **貿易収支** |
| 中国の非製造業PMI | **RatingDog(旧財新)非製造業PMI** |
| 米国のサービス業PMI | **ISM非製造業景況指数** |

過去の英語名称との対応は、読者向け表示ルールや共有仕様には記載せず、必要な場合に限り内部の修正台帳・照合ログで追跡します。対象期間は必要に応じて日本語名称の末尾に全角括弧で付記します。例：`貿易収支（2026年6月）`。国・地域が名称だけで判別できない場合は、国・地域欄を併用し、同じ情報を不必要に重複させません。

## 3. 日本時間の表示規則

読者向けの見出し、カード、表、本文では **「日本時間」** と表記します。`JST` は、IANAタイムゾーン名、`data-*`属性名、機械検証用フィールド、ソースログ等の内部用途に限り使用できます。読者向けに `（JST）`、`JST時刻`、`JSTの日付` を表示してはなりません。

## 4. スマホ閲覧時の必須仕様

### 4.1 対象画面幅と共通条件

320px、343px、360px、375px、390px、414pxのすべてで、横スクロール・文字重なり・切断・左右への不自然な偏りがないことを必須とします。

| 要素 | 必須仕様 | 禁止事項 |
|---|---|---|
| ヘッダー | タイトル、対象期間、レポート種別、作成日が必要に応じて縦に折り返され、互いに重ならない。ヘッダー右側は折返し可能なflex幅とする。 | 作成日を絶対配置しタイトルと重ねること、ヘッダー内の`white-space:nowrap`、固定幅による横方向のはみ出し。 |
| 3中核見出し帯＋BTC補助見出し帯 | `EA運用タイムテーブル`、`対象週の注目イベント(日本時間)`、`EAリスク管理ポイント`、`土日のBTC/USD EA運用に関する重要ガイド`を、本文幅内で中央揃えにする。BTC補助見出し帯はEAリスク管理ポイントの後・フッター前に置く。 | 左寄せ、可視`h1`〜`h6`、ページ幅を越える固定幅、BTCガイドをEAリスク管理の内部カードとして混在させること。 |
| 日付親カード | 日付・曜日・当日の重要イベント件数を中央揃えで折り返し可能に表示する。 | 子カードごとに日付を重複表示すること。 |
| イベント子カード | 時刻を上段の独立ラベル、国・地域／日本語名称／重要度／数値を下段に配置する。 | 固定幅の横並び時刻列、`min-width:92px`、時刻と本文の圧縮競合。 |
| テキスト | ヘッダー・作成日・日本語名称を自然に折り返し、単語途中の切断・右寄せ・横スクロールを発生させない。 | `overflow-x:auto`、`white-space:nowrap`によるヘッダー・本文・イベント名の横流し。 |

### 4.2 必須クラス・属性

生成HTMLとWordPress用HTMLには、以下の監査可能な構造を保持します。

| 目的 | 必須構造 |
|---|---|
| 見出し帯 | `ea-section-band` を持つ要素。`text-align:center`、本文幅に収まる幅、可視`h1`〜`h6`不使用。 |
| 日付親カード | `ea-date-group` と日付別の件数属性。 |
| イベントカード | `ea-event-card`、`ea-event-time-block`、`ea-event-content`。 |
| 日本語名称 | `data-ea-event-display-name-ja` と `data-ea-event-name-source`。 |
| 構造検証 | ヘッダー、3中核見出し帯、独立BTC補助見出し帯、日付親カード、全イベントカードを320〜414pxの6幅で自動検査する。 |

## 5. 生成・公開可否の必須ゲート

HTML生成前に根拠台帳で日本語名称の4フィールドを確定し、`🟢確認済み`以外を残してはなりません。生成後は次の検査を順に通過しなければ公開・完成版納品をしてはなりません。

1. 根拠台帳の必須フィールド、イベント日時、出典、重要度を検査する。
2. 生成HTMLとWordPress用HTMLのイベントID、日付、時刻、値、**日本語表示名**を台帳と照合する。
3. `SECTION 04`、`SECTION04`、読者向け`JST`、旧英語イベント名、横並び時刻列、`min-width:92px`、ヘッダーを含む`white-space:nowrap`、可視見出しタグの残存を検索する。
4. 320・343・360・375・390・414pxで自動ブラウザー検査を行い、320pxでは全領域の目視確認記録を残す。
5. 公開可否ゲートでERROR 0、WARNING 0、未解決の要確認項目0を確認する。

いずれか1つでも不合格なら **HOLD（配信保留）** とします。

### 5.1 BTC週末EAガイドの固定構成・判断規則

BTC/USDを週末に運用するEA週次レポートでは、独立補助セクションとして次の4カードを必須とします。

1. **週末も価格変動に備える**：土日に定例の主要経済指標が少なくても、BTC/USDは24時間取引されることを説明する。
2. **確認する場所と3段階の判断基準**：ニュース・公式発表、USDC/USDT、取引環境・テクニカルの各区分で、`稼働停止（Lot 0）`、`Lotを通常の50%以下へ抑制`、`通常稼働`の基準と参考URLを併記する。
3. **Lotを抑える場合の設定例**：通常0.10 Lotなら0.05 Lot以下という例を示し、最小Lot単位に合わせて端数を切り下げる旨を明記する。
4. **再開または通常Lotへ戻す前の確認**：停止・Lot抑制の原因が解消し、MT4/MT5の価格配信、スプレッド、約定状況が通常へ戻ったことを確認する。

`稼働停止`は新たな戦争勃発、緊急利上げ、主要取引所への重大な規制・取引停止、USDC又はUSDTの$0.99明確割れ、`Major Outage`、又は一方向の価格ブレイクとスプレッド拡大継続のような異常時に限ります。`Lotを通常の50%以下へ抑制`は、地政学的緊張、USDC又はUSDTの$0.99台前半での不安定推移、`Degraded Performance`、又は通常より広いスプレッド・短時間の大きな変動がある場合に適用します。固定的な「1時間で○%」の停止基準は使用せず、各EAの設定、対象銘柄、ブローカー条件、過去検証結果と併せて判断します。SNSの投稿だけで判断せず、速報と公式発表の両方を確認します。

## 6. 旧ルールの処置

| 旧表現・旧構造 | 処置 |
|---|---|
| `SECTION 04`、`SECTION04`、旧イベント見出し（EA週次の読者向け表示） | 使用禁止。`対象週の注目イベント(日本時間)`へ統一。 |
| `（JST）`、`JST時刻`（読者向け表示） | 使用禁止。`日本時間`へ統一。 |
| 英語の経済指標名 | 読者向け表示は禁止。内部名・公式名として台帳へ保持可。 |
| `min-width:92px`の時刻列、横方向のイベントグリッド | 使用禁止。時刻上段の縦積みカードへ統一。 |
| 左寄りまたはページ全幅へ伸びる見出し帯 | 使用禁止。本文幅内・中央揃えへ統一。 |
| ヘッダー・レポート種別・作成日の`white-space:nowrap`又は固定幅 | 使用禁止。自然な折返しと`overflow-wrap:anywhere`を用い、狭幅では縦積みに移行する。 |
| 旧カレンダー複製 | 使用禁止。共有カレンダーの正本は `calendar_weekly.md` のみ。 |
